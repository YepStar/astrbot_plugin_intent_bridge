# AstrBot 自然意图与插件整合

让用户用日常语言调用已经安装的插件，把分散的工具和指令整理到同一个能力面板。

**当前版本：0.5.1 · AstrBot ≥ 4.29.1、< 5 · 当前声明支持 aiocqhttp**

例如，“把上一张图存成表情”“查一下这款游戏的近期评价”，可以在相关插件已安装、已配置且授权后，交给对应能力处理；最终仍由当前聊天 Agent 沿用原人格回复。

## 它解决什么问题

安装多个插件后，用户往往需要记住不同的指令，模型也未必能稳定找到合适的工具。本插件负责连接**用户意图、可用能力和原插件执行入口**：

| 主体功能 | 能做什么 |
|---|---|
| 上下文意图路由 | 结合当前消息和近期文字上下文，从本轮真实工具目录中选择能力、提取参数；普通聊天可以不调用任何工具。 |
| 内置指令接入 | 把管理员显式授权的插件指令转换为结构化工具，供主 Agent 调用；无需另装指令转换插件。 |
| 统一能力面板 | 按父插件与子指令查看能力，搜索中文说明、管理接入和授权，查看最近执行状态。 |
| 常用能力编排 | 对已适配的常用工具支持回答前执行，随后把真实结果交给主 Agent 组织回复。 |
| 自然语言表情收藏 | 识别明确的收藏要求，使用当前图、引用图或同会话同发送者的近期图片，经表情管理器校验后入库。 |
| 纠错重匹配 | 用户明确指出匹配错误时排除上次能力，允许一次重匹配；执行失败或超时不会据此自动重做动作。 |

## 定位与适用场景

本插件处于**聊天入口与功能插件之间的编排层**。它负责发现和选择入口，具体能力仍由原插件实现。

```text
用户消息 → 当前会话的能力目录 → 意图分类与参数校验
                                  ↓
                 原生工具 / 已授权指令 → 原插件执行
                                  ↓
                         主 Agent 沿用人格回复
```

适合已经安装多个功能插件，希望减少记忆指令成本、统一能力管理，或逐步给现有指令增加自然语言入口的用户。也适合同时运行不同私聊与群聊配置的机器人：按完整会话 UMO 显式授权，原插件继续决定各自的数据范围和会话权限。

如果只使用普通聊天或少量固定指令，原生 Agent 与原指令可能已经足够。它也不替代业务插件、记忆系统、语音合成服务或平台适配器；外部服务是否可用，仍取决于原插件的配置、连接和配额。

## 插件优势

- **使用真实目录**：根据本轮已经开放的工具及 JSON Schema 分类，执行前再次检查可用性、会话权限与参数，减少过时能力被误调用。
- **保留原执行链路**：传递原始事件身份，通过 AstrBot 工具执行器或内置指令服务执行，不让分类模型直接操作插件内部状态。
- **适度自动化**：常用能力可预执行；一般新工具和授权指令交给主 Agent 原生调用。失败、超时或分类异常时保留原聊天流程，不凭空宣称完成。
- **可见、可控**：面板管理的是本插件的路由接入与指令授权，插件本身的启停仍在 AstrBot 系统插件页操作。
- **逐步接入**：标准原生工具可自动发现；只有需要额外业务语义的能力才增加适配逻辑，避免把每个插件都变成强制依赖。

正常回合最多一次分类模型请求；明确纠错或格式无效时最多增加一次，共用分类超时。因此会增加一定的模型调用成本和等待时间。

## 与其他插件的关系

下列均为按需使用的能力来源，**无需为了安装本插件而安装整套生态**。

| 能力来源 | 本插件负责什么 | 原插件继续负责什么 |
|---|---|---|
| AstrBot 原生 `llm_tool` / 已接入 MCP 工具 | 自动收集本轮开放的工具，选择入口、校验参数 | 工具定义、权限、执行结果及平台行为 |
| 普通指令型插件 | 将显式授权的指令转为工具，保留参数与管理员检查 | 指令本身的业务逻辑和会话限制 |
| 陪伴、图像、日程等插件 | 对已适配工具编排生图、换装、备忘、资料读取等请求 | 人格、素材、日程解析、生成服务与确认流程 |
| 语音服务与陪伴语音增强 | 传递本轮语音/文字偏好 | 实际合成、音色、强约束及消息发送 |
| B站、小黑盒检索插件 | 提供 `bridge_research` 只读研究入口 | 登录状态、搜索及内容读取；没有通用网页工具时不等于全网检索 |
| 音乐插件 | 对已支持的一起听邀请提供衔接，使用开放的状态工具 | 音乐账户、房间连接及平台限制 |
| 表情管理器 `meme_manager` | 把用户明确要求收藏的真实图片交给入库流程 | 图片校验、去重、写入与语义索引 |
| 长期记忆或自学习插件 | 调用当前会话实际开放的记忆工具 | 数据存储、召回策略、私聊与群聊是否共享等部署选择 |

公开版本不绑定特定人格、账号、模型供应商或记忆分工。群聊/私聊授权由用户配置，记忆隔离由相应插件和 AstrBot 会话配置负责，本插件不会替用户改写这些策略。

## 安装与开始使用

1. 在 AstrBot 插件管理中，通过本仓库地址安装，确认依赖 `jsonschema`、`pypinyin` 已安装。
2. 选择一个要启用的会话，发送 `/sid`，将完整 UMO 填入本插件 `allowed_umos`。支持 `FriendMessage` 和 `GroupMessage`，默认空列表，不自动启用任何会话。
3. 在插件页面打开 `control`，点击“刷新插件与能力”。原生工具按当前会话可用范围参与路由；指令需要在“指令接入”中逐项授权。
4. 按需设置分类模型和自动预执行，再用已安装插件能完成的简单请求验证效果。

授权群聊不表示原插件的所有能力都支持群聊；管理员权限、原插件开关、会话过滤和必要的确认仍然生效。刷新能力不会执行指令，也不会自动授权所有管理功能。

### 从独立指令转换器迁移

0.5.0 起已内置指令服务。首次加载会尝试读取 `astrbot_plugin_command_tools` 的旧授权和超时设置，随后保存在本插件配置中，保留 `cmd_*` 工具标识和 `/cmdtools` 管理入口。

迁移前备份两个插件及配置，先停用旧转换器，再加载本插件并核对授权和工具；确认后可卸载旧转换器。不要同时启用两套同名指令工具。

### 常用配置

| 配置项 | 默认值 | 用途 |
|---|---|---|
| `enabled` | `true` | 是否启用语义路由；不等同于关闭已授权指令工具。 |
| `allowed_umos` | `[]` | 允许自然语言预路由的完整会话标识。 |
| `router_provider_id` | 空 | 分类模型；空值跟随当前会话模型。 |
| `enable_preflight` | `true` | 常用能力回答前预执行；关闭则交主 Agent 原生调用。 |
| `enable_speech_intent` | `true` | 识别并传递本轮语音/文字偏好。 |
| `extra_auto_tools` | `[]` | 额外允许预执行的工具名，仍须通过当前工具目录与权限检查。 |
| `router_timeout_seconds` | `12` | 分类总超时，单位秒。 |
| `dispatch_timeout_seconds` | `180` | 单个原生模块执行超时，单位秒。 |
| `allowed_commands` | `[]` | 指令接入授权，由统一面板或 `/cmdtools` 管理。 |
| `command_timeout` | `30` | 指令执行超时，单位秒。 |
| `enable_meme_save` | `true` | 是否允许明确要求的表情收藏，仍需表情管理器及管理员权限。 |

搜索数量、小黑盒 Profile、收藏分类和路由暂停工具等选项见插件配置页。图片近期引用仅保存在内存中，最长五分钟、最多四张；收藏成功不代表语义索引已经完成。

## 扩展性与解耦方式

**新增标准工具**：插件提供标准 `llm_tool`，或通过 AstrBot 接入 MCP，并向当前会话开放后，即可进入本轮目录。工具描述和 Schema 应说清用途与参数，通常无需为不同自然说法新增关键词。

**接入现有指令**：优先在面板逐项授权。文本指令可转换为结构化工具，富媒体结果会沿执行链路返回。需要附件、按钮或复杂多轮状态的指令不能仅靠文本合成事件自动适配，应由原插件提供原生工具或增加专用适配器。

**报告运行就绪状态**：插件可选实现同步或异步的 `intent_bridge_tool_ready(name) -> bool`。本插件据此过滤未就绪工具；未实现时仍按工具注册、原插件会话范围和执行时检查处理。注册成功不代表外部服务已经连通。

**选择预执行范围**：一般工具交主 Agent；希望额外工具参与回答前执行时，按需加入 `extra_auto_tools`。跨会话发信、发布和管理类能力不会因配置该列表就绕过排除规则。

当前实现仍包含照片、语音、音乐、检索等已知插件的工具名及就绪检查。这些属于可选适配，不应理解为任意插件都能零配置完成复杂工作流。分类、能力发现、执行、指令服务与控制面板分属独立模块，扩展时优先增加适配，保持原插件业务逻辑独立。

### 语音兼容

语音偏好通过事件属性交给实际语音实现。使用陪伴插件 6.7.0 时，可参考 [兼容补丁](compat/private_companion_tts.patch)；是否适用取决于目标版本，升级后需重新检查。补丁不等于独立 TTS 服务，也不保证朗读接口能真正唱歌。

## 开发与验证

在具备 AstrBot 源码和依赖的 Python 环境运行：

```sh
# 指向用于测试的 AstrBot 源码目录
export ASTRBOT_SOURCE=/path/to/AstrBot
export PYTHONPATH="$ASTRBOT_SOURCE${PYTHONPATH:+:$PYTHONPATH}"
python -m pip install -r requirements-dev.txt
python -m pytest tests command_tests -q
```

本版在隔离目录中通过 328 项测试，覆盖会话授权、原生工具路由、指令服务、面板校验及语音兼容；未向聊天平台发送消息或调用付费生成服务。

可选集成测试通过 `MEME_MANAGER_SOURCE` 指定表情管理器源码目录，通过 `COMPANION_TTS_SOURCE` 指定陪伴语音源码文件。语音测试会在未找到源码时跳过；要测试兼容补丁，应指定已应用补丁的目标源码。测试不代表外部账户、付费接口或所有平台已经端到端可用。
