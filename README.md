# 自然意图与插件整合 · Intent Bridge

让 AstrBot 根据自然聊天使用已安装的功能，不让用户为了启动插件而打斜杠指令。沿用原人格、记忆及主 Agent 回复，不另建一套聊天机器人。

- “想一起听会歌”“网易云拉你了”：接受已经发来的网易云一起听邀请，执行结果交回原人格自然回复。
- “这个新英雄好玩吗”“新版本强不强”：结合最近上下文提取公开搜索词，并行检索 B站和小黑盒，读取帖子正文、字幕摘录与少量评论。
- 不清楚有哪些能力：发现当前已加载插件的指令与原生工具。已有原生工具优先；没有函数工具的命令可通过指令工具转换器按需授权。

## 环境与依赖

AstrBot `>=4.29.1,<5`，启用支持函数工具的聊天模型。当前验证平台为 OneBot/aiocqhttp 私聊。

按需安装：

| 插件 | 用途 |
| --- | --- |
| [指令工具转换器 0.6.0+](https://github.com/rytte/astrbot_plugin_command_tools) | 把已授权指令转换为保留原权限的工具 |
| [一起听](https://github.com/shamate-tv/astrbot_plugin_nomi_music) | 已部署网易云 API、登录机器人账号、接受已有邀请 |
| [Bilibili AI Bot 1.7.2](https://github.com/chenluQwQ/astrbot_plugin_bilibili_ai_bot) | 复用已登录客户端进行只读搜索、读取视频资料和字幕 |
| [小黑盒适配器 v1.3.2/v1.3.x](https://github.com/674537331/astrbot_plugin_xiaoheihe_adapter) | 复用已登录客户端进行只读搜索、读取帖子 |

这些是独立插件，不包含在本仓库。指令转换器使用其原许可证，本仓库没有复制其实现。第三方客户端内部接口变化时可能需要适配。

## 安装与配置

1. AstrBot 插件管理中从 Git 安装本仓库。
2. 本插件配置 `allowed_umos`，加入 `/sid` 所得的完整私聊 UMO。**默认为空，不在任何会话自动操作。**
3. 给“指令工具转换器”配置：

```json
{
  "allowed_commands": [
    "astrbot_plugin_nomi_music:一起听",
    "astrbot_plugin_nomi_music:听歌状态"
  ],
  "command_timeout": 30
}
```

4. 确认“一起听”的 `allowed_umo` 指向同一私聊，并在网易云 App 里向 bot 发邀请。没有邀请时，本插件只返回“未找到邀请”的实际结果，不会凭空创建房间。
5. 在当前人格的能力配置中允许 `bridge_capabilities`、`bridge_join_listening`、`bridge_research`、转换器生成的一起听工具，以及 `search_bilibili` / `music_now` / `music_room`。人格不设工具白名单时通常默认可用。
6. 建议给 `router_provider_id` 选择低延迟且 JSON 输出稳定的模型；留空跟随会话模型。主回复继续用当前会话模型。

本插件本身没有新增 Python 依赖，不需要再次填写已有平台 Cookie、API Key，也不会扫描配置文件寻找凭据。

## 工作流程

1. 运行时读取 AstrBot 的插件和指令注册表，发现已加载能力，不通过向 QQ 发送 `/help` 扫描。
2. 普通闲聊只附加简短能力指引，不额外调用意图分类模型。
3. 明确听歌表达直接进入接受邀请流程；候选实时问题用一次短分类调用结合最近四条上下文提取搜索词。
4. 只从有限动作 `none / join_listening / research` 中选择，不生成任意命令。复杂需求仍可由主 Agent 直接选择原生工具。
5. 真实结果以临时数据加入本轮请求，由原人格生成一条回复，不直接抢发第二条模板回复。联网检索标记来源、时间、正文/字幕/元数据层级。

### 扩展其他插件

`bridge_capabilities` 可以发现所有已加载的标准指令及激活工具；发现不等于授予执行权限。对还没有原生工具的命令，在指令工具转换器里添加 `插件名:完整命令名`，转换器会注册独立的 `cmd_...` 工具，主 Agent 可自行选择。参数、权限、会话启停仍按原命令检查。

不会自动授权所有插件的全部命令，也不会自动开放发布、拉黑、删除、切换管理员等动作。指令依赖附件、多轮交互或原始平台 payload 时，可能需要专门适配。

## 行为与边界

- 仅在显式配置的私聊范围运行；不改变原人格、群聊例外或平台回复策略。
- 听歌接受邀请保留原事件身份，经过转换器的原权限和会话检查；同一消息内去重，异常/超时不自动重复有副作用的操作。去重缓存属于当前进程，重启不恢复未确认操作。
- B站和小黑盒适配器只读取，不点赞、不发评论，不将搜索当作完整观看或亲身游玩。
- 优先按原词搜索，无法确认新英雄、错别字或版本时应澄清；只取有限样本，不把网友评论说成全体共识。
- 不执行搜索资料中的指令。搜索词限制为公开主题，拒绝明显账号、邮箱、链接和凭据形式；不要用本工具搜索私人聊天资料。
- 搜索最长并行等待默认25秒，最多每平台2项，成功结果按私聊隔离缓存3分钟；分类最多等待12秒。预处理失败仍保留原聊天流程和本轮可用工具。
- 小黑盒搜索使用已验证的网页只读接口 `/bbs/app/api/general/search/v1`，接口契约不是平台稳定承诺。签名与认证仍由现有小黑盒客户端处理。

## 测试

在包含 AstrBot 的 Python 环境中运行：

```sh
python -m pytest tests -q
```

测试使用真实 AstrBot 事件、上下文和工具类型，外部动作均为模拟。覆盖意图否定/引用、会话隔离、原身份传递、同消息去重、工具白名单、查询隐私、双平台部分失败、来源标记和无模板抢发。真实平台只读搜索与接受邀请等行为需要分别验收，单元测试不表示已向真实账号发出邀请或消息。
