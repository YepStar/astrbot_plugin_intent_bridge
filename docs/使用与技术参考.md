# 冷月系—自然意图分析

当前版本：**0.6.2**。调用记录分为实际调用与未调用两层；实际调用显示在主界面，未调用记录从按钮进入内层窗口。129项回归测试通过。

0.2.0 将私聊语音、图片和常用插件能力合并为一次上下文语义分析。读取本轮真实原生工具的说明及 JSON Schema，选择能力和参数，然后通过 AstrBot 原执行器运行；主聊天 Agent 仍负责沿用人格回应。普通聊天没有必要动作时不调用工具。

## 当前工作流

1. 仅处理 `allowed_umos` 中已授权的私聊；保留原事件、用户原话、人格和群聊策略。
2. 请求早期收集当前启用且对本会话开放的原生工具；检查已知模块内部开关和可选的插件就绪接口。
3. 用 `router_provider_id`（留空跟随会话模型）结合最近8条文字上下文，一次分析语音/文字偏好及最多3个必要工具调用。没有关键词候选门槛，不需要逐句增加触发词。
4. 验证名称在本轮目录、参数符合工具 Schema。请求末期再次检查权限、模块状态及参数，防止之前可用的工具后来被过滤。
5. 常用模块自动预执行；其他新发现的工具交主 Agent 按原生工具流程调用。结果注入本轮上下文；尝试过的工具和一起听别名移出本轮工具集，失败或超时不自动重复执行。
6. 分类异常时保留原主 Agent 及原模块行为，不伪造已完成动作。

## 常用模块预设

| 模块 | 原生工具/行为 |
|---|---|
| 照片、自拍、普通绘图、改图、定制角色贴纸 | `pc_generate_photo`；人物入镜 selfie、景物 text2img、改图 edit；现有照片走当前媒体工具 |
| 语音 | 事件级 voice/text/auto，由陪伴插件实际合成；不会另建 TTS 链路 |
| B站、小黑盒检索 | `bridge_research`：只读搜索、字幕/正文摘录及少量评论 |
| 通用网页检索 | 仅在现有网页工具及其内部配置实际启用时使用 |
| 音乐 | `bridge_join_listening` 接受已有邀请；`music_now` / `music_room` 查询 |
| 备忘与提醒 | `pc_manage_memo`，保留用户原时间表达交原模块解析；删除确认交原生 Agent 保存上下文 |
| 日程 | `pc_manage_schedule`，查看或按用户明确要求修改 |
| 创作资料柜 | `pc_view_creative_work` / `content_companion_view_work` 读取真实库存；临时创作留给主模型 |
| 衣柜及换装 | `pc_query_wardrobe_detail` / `pc_set_outfit_intent`，可组合换装后拍照 |
| 表情包 | `search_memes` / `pc_find_reaction_image`；依赖实际素材库 |
| 记忆 | `recall_long_term_memory` 等已开放的记忆读取工具 |
| 链接与媒体 | 使用现有解析、阅读工具，不把摘要声称为完整观看 |

预设只是工作流说明，不限制自然表达。“想看你的照片”“你在做什么，拍给我看看”可以调生图；只问“在干嘛”不因此自动生图。引用、否定、闲聊和已经结束的旧请求不当成新动作。照片是角色生成图，不冒充真实摄像头拍摄。

## 新模块如何加入

插件已加载、会话授权，并提供标准 `llm_tool`/MCP 工具后，会自动进入本轮能力目录，主 Agent 可以调用，不需要为每种新说法改代码。命令型插件须先在本插件的“指令接入”中显式授权转换，不能猜测或直接伪造聊天指令。

常用工具有内置预执行策略。希望新工具也在回答前执行时，将其工具名加入 `extra_auto_tools` 即可，无需改路由代码。参数、原模块权限及确认流程仍生效。跨会话发信、发布内容、封禁等管理工具不属于普通陪伴路由，不自动预执行。

插件可选实现异步或同步的 `intent_bridge_tool_ready(name) -> bool`，使路由在每轮检查该工具的运行就绪情况。未实现时依赖原生工具开放范围及模块自己的执行检查；工具注册不等于外部服务已连通。

不会自行开启全局关闭的插件或没有配置的硬件模块。素材库存、外部配额和连接状态可能在真正调用时失败，不能仅凭目录宣称已完成。

## 配置

- `enabled`：启用路由。
- `allowed_umos`：允许的完整 FriendMessage UMO，默认空。
- `enable_preflight`：常用工具自动预执行；关闭时将匹配结果交原生 Agent。
- `enable_speech_intent`：是否将语音分类结果交陪伴插件；不影响其他能力匹配。
- `router_provider_id`：分类模型，留空跟随当前会话。
- `router_timeout_seconds`：分类超时，默认12秒。
- `dispatch_timeout_seconds`：原生模块执行超时，默认180秒。
- `extra_auto_tools`：额外允许预执行的工具名列表。
- `results_per_platform` / `search_timeout_seconds`：搜索每平台数量及超时。
- `xiaoheihe_profile_id`：已配置的小黑盒 Profile，默认 default。

每回合最多一次分类模型请求，会增加相应调用成本与等待。目录不读取或发送插件凭据；搜索词限制为公开主题，不含私人账号、邮箱、链接和凭据。

## 语音兼容

陪伴插件6.7.0需要 [compat/private_companion_tts.patch](compat/private_companion_tts.patch)，本机已应用。它通过事件属性接收本轮语音/文字偏好：明确语音请求在弱约束下绕过自动语音冷却；文字偏好阻止自动转换及误写的语音标签。强约束仍生效。升级陪伴插件时需要检查补丁兼容。

语音成功后的文字展示沿用陪伴面板设置，本机为仅语音；合成失败留文字。唱歌/哼唱可识别，但目前朗读 TTS 不保证旋律或真正唱歌。

## 0.3.0：控制面板与真实表情收藏

在 AstrBot 插件列表中打开“自然意图与插件整合”的页面 `control`。

- 右上角“刷新插件与能力”扫描当前已加载插件、原生工具和指令注册表，同步内置指令接入已授权的工具。新原生工具可供语义判断；新指令在“指令接入”页逐项选择授权，刷新本身不执行指令、不自动授权所有管理功能。
- 原生工具页可暂停/接入路由。只影响本插件已授权私聊中的路由，不改动其他插件的全局启用状态。停用的插件或工具需要先在原插件启用。
- 设置页可控制路由、预执行、表情收藏、默认分类、授权私聊和分类模型；保存立即用于后续请求。
- 调用记录在本地保存最近500条用户原话、结构化路由选择和简要执行回执，重启保留；不保存图片、模型推理正文或完整工具输出，常见凭据脱敏。刷新记录不会执行动作。
- 所有API沿用AstrBot管理面板认证；页面使用原生Plugin Page SDK，不另开未认证端口。

### 发图后自然语言保存

已授权私聊的管理员发来图片，再说“保存这个表情”“把上一张收藏起来”，或者引用一张图要求“保存到开心分类”。工具 `bridge_save_received_meme` 通过表情包管理器的图片校验、整包去重、写入锁及原子保存函数入库，不会只口头答应。

支持当前消息、引用消息里的图片，以及同一私聊、同一发送者最近5分钟的图片引用；最多4张。保存前才读取图片内容，短期缓存不写磁盘；重启清空。过期或未拿到真实图片时请求用户重发。不接受模型虚构的URL或路径。默认分类为“用户收藏”；GIF原字节保存。自动收集仍可保持关闭，不会因此收集所有聊天图片。

只在当前消息明确要求保存时执行；否定和示例不执行，沿用表情管理器的管理员权限与当前会话插件启用限制。重复内容返回already_saved。图片入库不等于语义索引已完成，工具回执明确区分两者；需要语义检索时可在表情管理器语义化页面增量处理。新分类保存后由表情管理器同步目录。

### 指令接入的边界

内置指令接入只为授权指令生成结构化工具，沿用原指令权限和参数校验。它的合成事件只有文本，不能自动理解所有需要附件、按钮或多轮状态的指令；这些能力需要像表情收藏一样提供明确适配器。主Agent仍负责执行新授权的一般指令，原有常用工具才可预执行；涉及删除确认或跨会话动作仍受原模块控制。

### 中文注释

控制台显示中文名称和用途说明，保留原工具标识、指令和原插件说明，支持中文搜索。常用原生工具使用人工中文注释，原插件已有中文说明时直接复用；尚无中文说明的未知功能会明确标注，不猜测其行为。指令转换出的工具按原始完整指令标注。中文注释也加入意图分类提示词，底层工具名、参数和原指令权限不变。

### 0.4.0：父子目录与纠错重匹配

能力目录改为父插件与子指令双栏；刷新扫描本机安装目录并自动翻译新增外文说明。插件启停仍只在 AstrBot 系统插件页操作。新增明确纠错后的排除、一次重匹配及会话隔离的拒绝偏好，详见 [更新说明](CHANGELOG.md)。

AstrBot插件页面iframe没有allow-modals，浏览器会抑制window.confirm并直接返回false。控制台改为页面内确认框，不改变iframe权限；确认后才发送授权请求。支持取消、Escape关闭、键盘焦点约束，以及保存中和失败反馈。

## 0.5.0：内置指令接入

无需独立安装 astrbot_plugin_command_tools。首次加载自动迁移原授权名单和执行超时，保存到本插件配置，后续不再依赖旧配置文件；已有 cmd_* 工具名称保持不变。统一控制面板和管理员 /cmdtools 均可管理授权。权限、会话、父子命令、参数验证、富媒体回复及失败不重试规则保持生效。命令工具随本插件启停；enabled 和 allowed_umos 仍只控制语义预路由，不能替代原命令权限。

迁移前应备份两个插件与配置。先停用旧转换器，加载本版本并确认原授权和工具恢复，再卸载旧插件；切勿同时启用两个转换实现，以免同名工具冲突。

验证环境：MEME_MANAGER_SOURCE 可指定本机表情管理器源码目录；ASTRBOT_SOURCE 可指定 AstrBot 源码目录。


## 调用记录（0.6.0）

控制台的「调用记录」按用户消息记录：原话、时间、消息ID、会话、记录编号、分类模型、解析并验证后的工具/指令及参数、预执行或交主对话继续的状态，以及后续真实工具调用的简要回执。原指令会显示 `/指令`，原生工具显示工具标识及中文用途。可按原话、工具、指令或编号搜索并翻页。

记录保存在插件数据目录的 `route_records.json`，最近500条、文件权限0600、重启保留。只记录已授权私聊中的新消息，不伪造补齐历史记录；API Key、Cookie 等常见凭据脱敏。不保存模型推理正文或完整工具返回。主对话在搜索之后继续选择的工具会单独列入实际调用，不能把“已匹配”当成“已执行成功”。记录写入失败不影响原路由和工具执行。面板沿用 AstrBot 登录验证。

### 调用记录分层（0.6.2）

主列表仅显示 executions 非空的消息记录，包括进行中、失败和结果未确认的调用。没有实际调用的记录从“未调用记录”按钮进入内层窗口查看，包含普通聊天、待执行计划和分析失败。两层独立搜索和分页，后端先分类再分页；关闭窗口保留主列表位置，原始记录及500条保留策略不变。

## 功能与本地配置分离

功能实现、兼容处理和界面改动直接维护在本插件仓库。账号绑定、权限白名单、Provider ID、Cookie、Token及其他私人配置保留在AstrBot本地配置或plugin_data，不纳入源码发布。升级功能源码时保留已有本地配置与数据。
